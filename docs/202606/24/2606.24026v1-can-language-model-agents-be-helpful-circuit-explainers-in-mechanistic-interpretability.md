## 摘要
机械可解释性在自动定位电路方面取得了显著进展，但解释已定位组件的作用仍然劳动密集且难以标准化。在本工作中，我们研究一旦电路已被识别，语言模型（LM）代理能否协助这一解释问题。我们引入AgenticInterpBench，一个由84个半合成变压器电路和163个组件级注释构建的电路解释基准。我们提出HyVE（假设、验证、解释），一个通过观察、假设生成和因果验证的迭代循环分析每个组件的代理解释器，最终生成组件级解释和电路级任务描述。在四个LM骨干模型上，HyVE恢复了有用的组件级和任务级解释，但没有一个骨干模型是统一最优的。我们的分析表明，强大的骨干模型通常形成基于观察的假设，而失败更常出现在验证循环的后期，由于不完整的验证计划、代码执行错误或未解决的假设。在Llama-3-8B的算术电路上的案例研究表明，相同的公式可以扩展到半合成基准之外的自然训练模型。总体而言，LM代理是有前途的电路解释器，但可靠的验证仍然是主要障碍。

## Abstract
Mechanistic interpretability has made substantial progress in automatically localizing circuits, but explaining what localized components do remains labor-intensive and difficult to standardize. In this work, we study whether language model (LM) agents can assist with this explanation problem once a circuit has already been identified. We introduce AgenticInterpBench, a benchmark for circuit explanation built from 84 semi-synthetic transformer circuits with 163 component-level annotations. We propose HyVE (Hypothesize, Validate, Explain), an agentic explainer that analyzes each component through an iterative loop of observation, hypothesis generation, and causal validation, eventually producing a component-level explanation and a circuit-level task description. Across four LM backbones, HyVE recovers useful component- and task-level explanations, but no backbone is uniformly best. Our analysis shows that strong backbones usually form observation-grounded hypotheses, while failures more often arise later in the validation loop, through incomplete validation plans, code execution errors, or unresolved hypotheses. A case study on an arithmetic circuit in Llama-3-8B shows that the same formulation can extend beyond semi-synthetic benchmarks to naturally trained models. Overall, LM agents are promising circuit explainers, but reliable validation remains the key obstacle.

## 2. 方法论：核心思想、关键技术细节与算法流程
- **核心思想**：提出 **HyVE（Hypothesize, Validate, Explain）** 代理解释器，对电路中每个组件执行迭代的“观察→假设生成→验证”循环，最终输出组件级角色标签和自然语言描述，以及电路级任务描述。
- **关键技术细节**：
  - **观察阶段**：代理编写结构化观察计划，调用TransformerLens等工具获取组件的激活模式、注意力分布等，进行代码执行并总结观察结果。
  - **假设生成阶段**：基于观察和任务输入-输出示例，提出一个可验证的短假设（不接触角色分类标签，避免约束推理）。
  - **假设验证阶段**：设计因果干预实验（如激活修补、均值消融、互换干预等），编写代码执行，根据结果决定支持或反驳。若反驳则返回假设生成阶段（最多3次迭代）。
  - **分类阶段**：所有组件处理后，给定角色分类法（5类：INDICATOR, AGGREGATOR, COMBINER, ROUTER, MAPPER），代理为每个组件选择最匹配的标签并写简短描述。
  - **总结阶段**：合成组件级解释，输出信息流描述和推导出的任务描述。
- **算法流程**：状态机实现（LangGraph），每个组件独立处理，观察和验证均使用工具调用（读文件、执行Python），代码在沙盒子进程中运行，最多5次执行尝试。

## 6. 主要结论与发现
- LM代理能产生有用的电路解释，但没有一个骨干模型在所有指标上统一最优。
  - Claude-Sonnet-4.6在组件标签准确率（79%）和代码执行成功率（93%）上最高。
  - Gemini-3.1-Pro在角色描述质量和任务准确率上最佳（任务准确率83%），且成本较低。
  - GPT-5.4验证计划最合理但代码执行失败率高（52%执行成功率），限制了最终质量。
  - Qwen-3-Coder显著落后，假设扎根度低（仅41.2%完全扎根），且验证计划不完善。
- **失败模式**：强骨干通常在假设生成阶段表现良好（假设基于观察），但失败主要出现在验证循环的后期——验证计划不完整、代码执行错误、或假设未能在预算内解决。代码错误包括张量形状错误、API误用、BOS偏移等。
- **案例研究**：HyVE能扩展到真实模型，Claude正确解释8/10组件，GPT正确6/3部分正确。代理能区分因果主传输头与备份头。
- **总体结论**：LM代理是“有前途的”电路解释器，但**可靠的验证仍然是核心瓶颈**。

## 7. 优点
- **创新性**：首次提出LM代理用于电路解释的任务，并构建了专门的基准AgenticInterpBench。
- **方法论简洁有效**：HyVE的观察-假设-验证迭代循环模仿了人类研究者的工作流，结构清晰且可扩展。
- **深入分析失败模式**：不仅报告最终指标，还分解假设扎根、验证计划声音、代码执行错误等过程指标，指出瓶颈所在。
- **案例研究延伸**：在半合成基准外，验证了在真实Llama-3-8B上的可行性，且揭示了代理能发现“因果冗余但logit-lens阳性”的组件。
- **人类验证与LLM法官一致性**：验证了LLM法官用于评估角色描述和任务描述的可靠性（κ≈0.75-0.86）。

## 8. 不足与局限
- **实验覆盖有限**：
  - AgenticInterpBench仅包含半合成电路，规模小、结构规则，不能代表自然训练模型中的复杂电路（如间接目标识别IOI电路规模更大）。
  - 未评估HyVE的端到端电路发现能力，仅假设电路已定位。
  - 案例研究仅一个电路（加法），可能无法泛化到其他行为。
- **潜在的偏差风险**：
  - 使用LLM法官评估自身输出（GPT-5.4作为法官可能偏爱自身），尽管采取了保守聚合和人类验证缓解，仍可能存在残余偏见。
  - 基准任务可能被LM后训练数据泄露（特别是IOI任务被排除），但作者已注意。
- **方法局限**：
  - HyVE的验证循环质量依赖于LLM的代码生成和因果推理能力，当前模型在执行复杂干预时容易出错。
  - 验证计划声音性评估主观，人类一致性仅为中等（κ≈0.46-0.48）。
  - 没有与现有自动化解释方法（如基于激活聚类或神经元重要性归因）对比，缺乏baseline比较。
- **应用限制**：成本较高（Claude方案$147），且依赖商业API调用，可复现性和可访问性受限。
