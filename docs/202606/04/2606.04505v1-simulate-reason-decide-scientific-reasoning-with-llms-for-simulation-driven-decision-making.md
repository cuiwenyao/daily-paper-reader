## 摘要
科学模拟器越来越多地被集成到基于大语言模型（LLM）的系统中，用于高风险的仿真驱动决策制定。然而，现有框架主要利用LLM来生成、校准或执行模拟器，将其视为黑箱接口，而非可推理的结构化机制系统。因此，当前方法缺乏识别、表示和推理模拟器行为背后的假设与机制的能力，限制了透明度、可审计性和决策合理性。我们提出MechSim，一个面向可执行科学模拟器的基于机制的神经符号推理框架。与先前主要对静态符号结构进行推理的神经符号方法不同，MechSim使LLM智能体能够推理科学模拟器的机制、假设和执行行为。我们的框架通过一个共享的结构化模式来表示模拟器，该模式捕获假设、变量、机制依赖和执行轨迹。在此表示之上，LLM智能体作为受约束的推理引擎运行，生成结构化的、基于证据的解释，将模拟器结果与其底层机制联系起来。我们在多个高风险领域评估了我们的方法，结果表明它提高了机制级别的解释质量、模拟器分析和下游决策的可靠性。

## Abstract
Scientific simulators are increasingly being integrated into LLM-driven systems for high-stakes simulation-driven decision-making. However, existing frameworks primarily use LLMs to generate, calibrate, or execute simulators, treating them as black-box interfaces rather than as structured mechanistic systems that can be reasoned about. As a result, current approaches lack the ability to identify, represent, and reason about the assumptions and mechanisms underlying simulator behavior, limiting transparency, auditability, and decision justification. We introduce MechSim, a mechanism-grounded neuro-symbolic reasoning framework for executable scientific simulators. Unlike prior neuro-symbolic approaches that primarily reason over static symbolic structures, MechSim enables LLM agents to reason about the mechanisms, assumptions, and execution behavior of scientific simulators. Our framework represents simulators through a shared structured schema capturing assumptions, variables, mechanism dependencies, and execution traces. On top of this representation, LLM agents operate as constrained reasoning engines that generate structured, evidence-grounded explanations linking simulator outcomes to their underlying mechanisms. We evaluate our approach across multiple high-stakes domains and show that it improves mechanism-level explanation quality, simulator analysis, and downstream decision-making reliability.

## 2. 方法论：MechSim 框架

### 核心思想
- 将神经（LLM）与符号（结构化模拟器表示）相结合，使 LLM 在**机制图**（Mechanism Graph）、假设、执行跟踪和敏感性分析结果等约束下进行推理，而非仅依赖表面输出。

### 关键技术细节
1. **上下文理解与知识检索**：一个 LLM Agent 从上下文信息 Ω 中提取决策相关实体、约束和初始条件，并从领域语料库中检索科学证据 Z（使用密集检索 + 重排序管道，类似 OpenScholar）。
2. **机制级基础化**：
   - **机制图构建**：对每个模拟器 s_i 构建有向图 G_i = (V_i, E_i, M_i)，节点为状态变量，边为机制转换，元数据包含假设 A_i、执行轨迹 τ_i 和统计摘要。
   - **模拟器校准与执行**：使用近似贝叶斯计算（ABC）校准参数分布，并在蒙特卡罗方式下运行（N≈300），产生输出 Y 和执行轨迹。
   - **敏感性分析**：对参数 θ_i 和结构假设 A_i 进行扰动，计算干预效果 Sensitivity(ϕ) = E[y|do(ϕ=ϕ2)] - E[y|do(ϕ=ϕ1)]，为推理提供实证支持。
3. **受约束的机制级推理**：推理 Agent 基于机制图、输出、敏感性结果和证据，通过追踪节点间传播路径生成结构化解释 E = (I, P, Z, C)：
   - I：输出解释（决策相关模式）
   - P：推理路径（带假设的节点序列）
   - Z：支撑证据
   - C：基于机制的声明
4. **验证检查**：验证 Agent 确保解释满足结构一致性（路径可追溯到图）、证据基础（与证据和输出一致）和实证支持（敏感性分析可验证）。若失败则迭代优化。

### 算法流程（文字说明）
1. 输入：上下文 Ω，任务 T，模拟器集合 S，语料 D
2. 上下文理解 Agent 提取结构化上下文和检索证据 Z
3. 机制建模 Agent 为每个 s_i 构建机制图 G_i，并执行模拟产生输出 Y 和轨迹
4. 敏感性分析 Agent 对参数和假设进行干预，计算效应
5. 机制推理 Agent 生成结构化解释 E
6. 验证 Agent 检查 E 的三要素，通过则输出最终解释和推荐 R；否则反馈给推理 Agent 修正

## 3. 实验设计

### 数据集 / 场景
- **COVID-19**：6 个区室模拟器（SIR, SEIRD, SEIRHD, SEIQRD, SEAIHRD, SIRV），Oracle 为随机多区室模型。真实数据来自 COVID-19 Forecast Hub（美国州/国家级别）。
- **供应链**：4 个模拟器（Base Stock, (s,S) Inventory, Multi-Echelon, Beer Game），Oracle 为随机多级供应链模型。数据来自 M5 数据集（Walmart 销售）。
- **麻疹**：6 个场景（默认合成、完美混合、伦敦前疫苗、芝加哥 2024 避难所、德州-新墨西哥疫情等），5 个模拟器（SIR, SEIR, SIRV, SVEIR, SVVIR），Oracle 为随机 agent-based 模型。

### Benchmark 任务
1. **政策选择**：对 6-9 个候选政策排序，指标 P@3, P@5, Recall@3, Recall@5

3. **解释评估**：用 LLM Judge 从完整性、机制逻辑一致性、科学合理性、忠实性（1-5 分）评估解释
