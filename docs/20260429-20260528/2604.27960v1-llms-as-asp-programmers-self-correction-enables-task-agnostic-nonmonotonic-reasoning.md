## 摘要
最近的大型语言模型（LLM）在推理方面取得了令人印象深刻的里程碑，但仍在高计算成本、逻辑不一致性和高复杂度问题上的性能急剧下降方面挣扎。虽然神经符号方法尝试通过将LLM与符号推理器耦合来缓解这些问题，但现有方法通常依赖于单调逻辑（例如SMT），这些逻辑无法表示可废止推理——人类认知的重要组成部分。我们提出了“LLM+ASP”框架，将自然语言转换为答案集编程（ASP），一种基于稳定模型语义的非单调形式体系。与先前需要手动编写的知识模块、领域特定提示或仅限于单问题类别评估的“LLM+ASP”方法不同，我们的框架无需任何每个任务的工程设计，并且统一适用于各种推理任务。我们的系统利用自动化的自我修正循环，其中来自ASP求解器的结构化反馈使得迭代改进成为可能。在六个不同基准上的评估表明：（1）稳定模型语义允许LLM自然地表达默认规则和例外，在非单调任务上显著优于基于SMT的替代方案；（2）迭代自我修正是性能的主要驱动因素，有效替代了手工领域知识的需求；（3）紧凑的上下文参考指南显著优于冗长的文档，揭示了“上下文腐烂”现象，即过多的上下文阻碍了约束遵循。

## Abstract
Recent large language models (LLMs) have achieved impressive reasoning milestones but continue to struggle with high computational costs, logical inconsistencies, and sharp performance degradation on high-complexity problems. While neuro-symbolic methods attempt to mitigate these issues by coupling LLMs with symbolic reasoners, existing approaches typically rely on monotonic logics (e.g., SMT) that cannot represent defeasible reasoning -- essential components of human cognition. We present "LLM+ASP," a framework that translates natural language into Answer Set Programming (ASP), a nonmonotonic formalism based on stable model semantics. Unlike prior "LLM+ASP" approaches that require manually authored knowledge modules, domain-specific prompts, or evaluation restricted to single problem classes, our framework operates without any per-task engineering and applies uniformly across diverse reasoning tasks. Our system utilizes an automated self-correction loop where structured feedback from the ASP solver enables iterative refinement. Evaluating across six diverse benchmarks, we demonstrate that: (1) stable model semantics allow LLMs to naturally express default rules and exceptions, outperforming SMT-based alternatives by significant margins on nonmonotonic tasks; (2) iterative self-correction is the primary driver of performance, effectively replacing the need for handcrafted domain knowledge; (3) compact in-context reference guides substantially outperform verbose documentation, revealing a "context rot" phenomenon where excessive context hinders constraint adherence.

## 2. 方法论：核心思想、关键技术细节与流程
- **核心思想**：让 LLM 作为 ASP 程序员，将自然语言问题描述转换为 ASP 程序，然后由 ASP 求解器（CLINGO）高效求解，并通过求解器的结构化反馈进行迭代自纠正，直到获得正确解或达到最大修订次数。
- **关键技术细节**：
  - **ASP 的非单调逻辑优势**：ASP 基于稳定模型语义，天然支持默认规则、异常、冲突推理，表达力强于单调逻辑（如 SMT）。例如：`flies(X) ← bird(X), not penguin(X)` 表示“除非有证据表明是企鹅，否则鸟会飞”。
  - **LLM 生成 ASP 代码**：给定问题描述和可选参考指南（标准版或紧凑版），LLM 生成具有模块化结构的完整 ASP 程序（包含 domain、generate、constraints、display 等模块）。
  - **自纠错循环**（如图 1 所示）：
    1. LLM 生成初始 ASP 程序。
    2. 运行 CLINGO 求解器，得到输出（可能包含解答、无解、错误信息）。
    3. 将求解器输出反馈给 LLM，LLM 决定是 **UPDATE（基于反馈修改程序）** 还是 **PASS（判定答案正确，结束循环）**。
    4. 重复直到达到最大修订次数（文中设为 10 次，平均仅需 2.18 次）。
  - **参考指南设计**：比较了无参考、标准参考（约 22k tokens，来自 CLINGO 手册）、紧凑参考（约 2.6k tokens，仅含常见构造）。紧凑参考显著更优，因避免了“上下文腐烂”。
- **与先前工作的区别**：无需任务特定提示、few-shot 示例或手动知识模块；自动处理错误恢复；应用于六种不同推理任务。

## 6. 主要结论与发现
1. **LLM+ASP 大幅优于基线 LLM**：平均准确率 78.0% vs 51.3%（相对提升 52.1%），尤其在困难问题上增益最大（如 ZL-XXL 提升 195%）。
2. **自纠错循环是性能的主要驱动因素**：无修订时平均 54.6%，有修订时达 78.0%，平均修订次数仅 2.18 次。较强模型（如 Gemini 2.5 Pro）每次修订改进更大，弱模型（DeepSeek V3）需要更多次修订仍效果较差。
3. **紧凑参考指南优于标准参考**：紧凑参考（2.6k tokens）在语法错误和遗漏约束方面均优于标准参考（22k tokens），揭示了“上下文腐烂”现象——过多上下文降低 LLM 遵循约束的能力。
4. **ASP 在非单调推理上显著优于 SMT**：在 MultiLogicNMR 和 BoardgameQA 上，LLM+SMT 表现甚至低于基线（因 SMT 无法自然表达默认否定），而 LLM+ASP 保持高水平。
5. **模型能力仍重要但差距缩小**：强推理模型（Gemini 2.5 Pro）达 93.9%，弱推理模型 DeepSeek V3 仅 45.0%；但引入 ASP 后，某些模型排序发生变化（如 Gemini 2.5 Flash 超过 o4-mini），表明不同能力（代码生成 vs 直接推理）在不同设置中权重不同。
6. **LLM+ASP 保持对困难的投入**：基线模型在困难问题上输出 token 数下降（放弃），而 LLM+ASP 单调增加，且 token 效率更高（每正确解 token 数更低）。

## 7. 优点：方法与实验设计的亮点
- **任务无关性**：统一提示模板，无需任何每任务工程（无 few-shot、无领域知识、无手动知识模块），直接在六个多样基准上工作。
- **自动自纠错**：将 ASP 求解器的反馈信号作为天然的错误指示，使 LLM 能迭代改进程序，替代了手工调试。
- **非单调形式主义的优势验证**：通过系统对比 ASP 与 SMT，证明了稳定模型语义在缺省推理、异常处理上的天然匹配，提供了有力实证。
- **紧凑参考设计**：指出并量化了“上下文腐烂”现象，并设计出高效参考指南，显著提升性能，具有实用价值。
- **详细的误差分析**：区分语法、超时、可满足但不正确、不可满足等错误类型，并分析不同设置下的分布变化，为后续研究提供方向。
- **效率考量**：LLM 生成紧凑 ASP 程序（而非直接搜索），结合高效求解器，实现 token 效率优于基线直接推理。

## 8. 不足与局限
- **模型能力依赖**：框架性能仍强烈依赖底层 LLM 的推理能力，弱模型（如 DeepSeek V3）即使多次修订也难达较好效果。
- **不可满足程序的调试困难**：当生成的程序无解时，求解器反馈极少，LLM 难以定位逻辑矛盾；可借助 unsat-core 提取（作者指出为未来工作）。
- **计算成本**：约 $4,200 的 API 费用（虽然相对不高），但对大规模应用可能仍需考虑。
- **评估范围有限**：仅限于约束满足、规划和非单调推理，未扩展到更开放的 NLP 任务或模糊问题。
- **BoardgameQA 的例外**：在该任务上 LLM+ASP 未显著优于基线，提示有些任务可能更适合 LLM 直接模式匹配（或数据污染）。
- **参考手册的一次性手动构建**：紧凑参考需人工提取关键构造，虽然比领域工程轻量，但仍需手动工作量（但消除了每任务工程）。
- **实验公平性讨论**：LLM+SMT 对比时，双方均未提供参考，但 LLM 可能对 ASP 训练数据更少（SMT 的 Python 绑定更常见），故 ASP 无参考时的劣势可能被低估；不过加入紧凑参考后 ASP 反超 SMT。
