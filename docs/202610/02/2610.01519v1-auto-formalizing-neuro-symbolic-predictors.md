## 摘要
神经符号（NeSy）预测器将先验知识融入神经网络的预测过程，确保输出满足指定约束，因而特别适用于必须符合领域知识的高风险应用。这一范式的关键瓶颈在于符号约束的获取：将领域知识编码为逻辑公式仍是一个依赖人工且专家密集的过程。在这项工作中，我们研究通过LLM进行自动形式化能在多大程度上系统地将文本知识转换为可插入NeSy预测器的符号知识。为此，我们提出了auto-nesy-bench，一个用于评估约束形式化及其对NeSy预测器下游准确率影响的新基准。通过对多个领域进行广泛评估，我们发现LLM能在有意义的程度上形式化约束，生成的公式通常与人类专家提供的公式相似。此外，当生成的公式在语法上有效时，它们能够带来高质量的下游预测。代码和基准见 https://unitn-sml.github.io/auto-nesy-bench/。

## Abstract
Neuro-Symbolic (NeSy) predictors incorporate prior knowledge into the prediction process of neural networks, ensuring that outputs satisfy specified constraints, making them particularly suitable for high-stakes applications where compliance with domain knowledge is essential. A key bottleneck in this paradigm is the acquisition of symbolic constraints: encoding domain knowledge into logical formulas remains a manual and expert-intensive process. In this work, we investigate the extent to which auto-formalization via LLMs can systematically translate textual knowledge into symbolic knowledge that can be plugged into NeSy predictors. To this end, we introduce auto-nesy-bench, a new benchmark for evaluating constraint formalization and its impact on downstream accuracy of NeSy predictors. Through an extensive evaluation across several domains, we find that LLMs can formalize constraints to a meaningful extent, generating formulas that are often similar to those provided by human experts. Moreover, when the generated formulas are syntactically valid, they can lead to high-quality downstream predictions. The code and benchmark are available at https://unitn-sml.github.io/auto-nesy-bench/.

## 1. 核心问题与整体含义

- **研究动机**：神经符号（NeSy）预测器（如 SPL）能够将领域知识作为逻辑约束注入神经网络，确保输出满足安全/结构要求，适用于自动驾驶、医疗等高风险场景。但这一范式的核心瓶颈在于**约束获取**——将领域知识手工编码为逻辑公式是专家密集型、昂贵且难以规模化的过程。
- **问题定位**：即使 DeepLog、ULLER 等新框架降低了 NeSy 的使用门槛，逻辑约束的形式化仍由终端用户承担。若用户没有领域专家，就难以部署 NeSy 预测器。
- **核心问题**：能否用大语言模型（LLM）充当"领域专家"，将自然语言知识自动形式化为可直接插入 NeSy 预测器的符号约束？以及这种自动形式化对下游预测精度有何影响？
- **整体含义**：本文首次系统性地研究了 LLM 自动形式化在 NeSy 预测器中的端到端流水线，并指出该方向可作为降低 NeSy 采用门槛、辅助（而非替代）领域专家的可行路径。

## 2. 方法论

### 2.1 核心思想
- 构建"自然语言 → 符号约束 → NeSy 预测器"的两阶段流水线：
  1. **自动形式化阶段**：LLM 接收约束的自然语言描述与接地变量列表，生成 CNF 公式。
  2. **下游集成阶段**：生成的 CNF 经知识编译转为可微概率电路，作为 SPL 的约束层或 SL 的软约束损失。
- 关键前提：**符号接地由人工提供**（给出完整变量名与含义），使评估聚焦于"约束是否正确"而非"符号是否正确识别"。

### 2.2 关键技术细节
- **五种输出格式**（均最终统一转换为 DIMACS）：
  - `DIMACS`：低层 SAT 求解器标准格式。
  - `NAT`：自然语言布尔表达式（AND/OR/NOT）。
  - `PySAT` / `CPMpy` / `SymPy`：Python 建模库，考察 LLM 生成代码的能力。
- **提示设计**：将 LLM 设定为 SAT/约束建模专家；要求输出包裹在 `<cnf>...</cnf>` 中；提供变量映射；区分 ZS 与 ZS-CoT 两种模式。
- **自验证机制**：最多 5 轮纠错，检测到语法错误后返回错误信息，LLM 需回复 `[[OK]]` 或 `[[FIXED]]` + 修正公式；同时自动修复格式问题（如 DIMACS 头部、Python 导入等）。
- **知识编译**：CNF 经 PySDD 编译为 SDD，再由 cirkit（SPL）或 KLay（SL）加载为可微电路。

### 2.3 评估指标（公式与算法流程）
- **基于模型计数（MC）的混淆矩阵**：
  - TP = MC(φ* ∧ φ̂)，FP = MC(¬φ* ∧ φ̂)，FN = MC(φ* ∧ ¬φ̂)，TN = MC(¬φ* ∧ ¬φ̂)
  - 变量数 ≤ 20 时精确计数，否则用 ApproxMC。
  - 对含 Tseitin 辅助变量的编码，先做投影 ∃A.φ̂ 再取反，避免虚假赋值。
- **F1 / Precision / Recall**：以有效赋值集合的匹配度衡量公式质量；**Recall 尤为关键**，因为 SPL 会把被错误排除的合法赋值永久置零。
- **新增三个 NeSy 专属指标**：
  - `REL`：生成公式与真值公式的关系（equal / strict / permissive / incomparable）。
  - `CON`：预测结果满足真值约束的比例。
  - `MC-R`：生成公式满足赋值数与真值满足赋值数之比，量化过宽/过严程度。

### 2.4 下游 NeSy 集成
- **SPL（硬约束）**：p_θ(y|x;K) = (1/Z_x)·q_θ(y|x)·c_K(y)，Z_x 为配分函数；对非法组合赋零概率。
- **SL（软约束）**：L_SL = −log Σ_{y|=K} Π_i p_θ(Y_i|x)，作为惩罚项与任务损失相加（λ=1）。

- **消融维度充分**：提示粒度、ZS vs. ZS-CoT、5 种输出格式、模型规模回归、问题复杂度回归、语法错误分类统计。
- **公平性**：
  - 每个模型使用官方推荐的解码超参数（temperature、top_p 等），未做额外调参。
  - SPL 的每个公式单独做超参数搜索（因为等价公式编译出的电路结构可能不同）。
  - 5 个固定随机种子（1011, 2021, 3031, 4041, 5051）报告均值±标准差。
- **总体评价**：实验覆盖较全面，消融充分，指标设计严谨（模型计数而非仅 SAT/UNSAT），公平性控制较好；但部分对比模型数量受算力限制（如 dcpbench 仅 4 个模型、satbench 仅 3 个模型）。

## 6. 主要结论与发现

- **RQ1（能否形式化）**：
  - 模型选择影响巨大：auto-nesy-bench 上 gpt-oss-120b 最优（F1=0.786），gemma4-31b 次之（0.706）；gemma3-27b 最差（F1=0.040，语法错误率 55.6%）。
  - 详细描述显著优于非详细描述（F1 0.330→0.455）。
  - CoT 普遍提升 F1（auto-nesy-bench 0.437→0.472；satbench 0.805→0.893）。
  - 代码格式（CPMpy、SymPy）在 auto-nesy-bench 和 dcpbench 上优于 DIMACS/NAT；但 NAT 在 satbench 上最佳（F1=0.920）。
  - 召回率普遍高于精确率 → 生成公式倾向于**过宽（permissive）**而非过严。
  - 最佳配置下 gemma4-31b 可达 F1=0.991（auto-nesy-bench）、0.992（satbench）。
- **RQ2（下游影响）**：
  - 使用详细提示时，LLM 生成公式在多数任务上与真值公式**等价（=）**，SPL 下游 ∆F1 与 ∆Recall 均小于 0.03/0.02。
  - 过宽公式（如 warcraft MC-R=1.75）对下游影响小，可在训练中被纠正。
  - 过严公式（如 kand-logic-2 MC-R=0.02）最有害，会永久排除合法预测。
  - 非详细提示下，仅约一半公式等价，∆F1 降至 −0.12 至 −0.15。
  - SL 对不完美公式更鲁棒（软约束），但一致性提升幅度有限，且过严公式会导致分类损失与语义损失冲突。
- **其他发现**：模型规模与性能仅弱相关（auto-nesy-bench 斜率 +0.338，p=0.113，不显著）；问题越大（变量/子句越多）F1 越低。

## 7. 优点

- **首创性**：首个面向 NeSy 预测器的端到端自动形式化基准与流水线，填补了 SAT/CP 基准与 NeSy 基准之间的空白。
- **评估指标严谨**：用模型计数代替简单的 SAT/UNSAT 判定，能区分过宽/过严/不可比，并引入 REL、CON、MC-R 三个 NeSy 专属指标。
- **符号接地解耦**：明确将符号识别与约束形式化解耦，避免评估混淆。
- **输出格式多样**：覆盖低层 DIMACS 到高层 Python 建模库，贴近真实工程接口。
- **自验证机制**：带格式自动修复的多轮纠错，工程上更实用。
- **下游闭环**：不仅评估公式质量，还实际训练 SPL/SL 验证端到端效果，包含硬约束与软约束两种范式。
- **基准设计细致**：auto-nesy-bench 提供两种粒度描述，便于研究"用户专业程度"的影响。
- **可复现性**：代码与基准开源，超参数、提示模板、错误分类均详细披露。

## 8. 不足与局限

- **逻辑表达力受限**：仅支持命题逻辑（PL）的 CNF，不支持一阶逻辑、SMT(LRA) 等更复杂形式；未来工作才考虑 DeepProbLog、LTN、ASP 等。
- **符号接地未自动化**：变量列表由人工提供，未评估 LLM 自动抽取符号的能力，而这在真实场景中可能是另一个瓶颈。
- **NeSy 方法覆盖有限**：仅使用 SPL 和 SL 两种代表性方法，未验证其他 NeSy 架构。
- **部分基准模型覆盖不足**：satbench 仅 3 个模型、dcpbench 仅 4 个模型，规模-性能回归不具统计显著性。
- **DCPBench 表现差**：最佳模型 F1 仅 0.433，说明复杂组合问题的自动形式化仍具挑战。
- **小模型失败率高**：qwen3-8b 和 olmo3-32b-think 在 18 个任务中分别失败 7/18 和 6/18，且失败模式包括 UNSAT、变量遗漏、运行崩溃等。
- **超参数搜索成本高**：因等价公式编译出的电路结构不同，需对每个公式单独调参，实际部署成本较大。
- **语法错误仍普遍**：即使经过自验证，gpt-oss-120b 仍有 7.8% 语法错误率，DIMACS 头部/子句计数等格式问题需额外自动修复。
- **潜在偏差风险**：提示模板、变量列表、约束描述均由作者人工撰写并协商统一，可能隐含作者对任务的先验偏好。
- **许可证限制**：SUSHI3 和 CIFAR 数据集不可再分发，需用户自行下载，可能影响基准的可复现性。
