# Dense Neuro-Symbolic Reasoning in a Unified Geometry State 

Ruoran Xu Wending Gao Haoyu Cheng Xiaoqiang Kang Qiufeng Wang †

Xi’an Jiaotong-Liverpool University 

## Abstract 

Geometry reasoning is naturally stateful: solving a problem repeatedly alternates between structural proposals and exact deductions. We formulate this process as 

dense neural–symbolic coupling , in which neural guidance and symbolic execution share a typed state and communicate through executable actions at every search step. Neural proposals contribute theorem instances, constructions, and algebraic bridges; the symbolic runtime applies registered rules, propagates exact constraints, and records provenance. A nested controller allocates computation first between neural and symbolic proposal sources and then among admitted actions. We instantiate the framework in O MNI -G EO , a single solver for plane, analytic (including conics), and solid geometry. With Claude Sonnet 4.6, O MNI -G EO reaches 94.2%, 88.5%, and 89.8% on FormalGeo7K, Conic10K, and SolidFGeo, respectively (90.8% macro average), and solves 21/30 IMO-AG-30 problems. 

## 1 Geometry reasoning as dense neural–symbolic interaction 

Geometry reasoning unfolds through intermediate mathematical states. The statement and diagram establish objects, relations, and quantities; subsequent steps introduce auxiliary structure, derive exact consequences, and connect them to the goal. Neural models are well suited to proposing structural moves from the full problem context, while symbolic engines execute registered theorems and algebraic consequences under explicit semantics. Their natural meeting point is the evolving formal state. We call their repeated state-level interaction dense neural–symbolic coupling . Every admitted action is executed before the next decision, and both reasoning sources condition on the updated state: 

st → C (st) → at → st+1 = T (st, a t), where C(st) is the admitted candidate set. A neural construction can therefore expose new symbolic consequences, while a symbolic deduction can immediately reshape the next neural proposal. The complete reasoning trace is built through this continuous feedback loop over the shared formal state. This formulation leads to three coupled requirements: a shared representation covering heterogeneous geometry domains, a typed transition contract that records the logical status and provenance of every accepted action, and adaptive allocation over both proposal sources and admitted continuations. OMNI -G EO realizes these requirements with G EO LIB and G EO DL, a common action interface, and nested source-UCB and action-PUCT search. Prior geometry systems establish structured text–diagram reasoning, learned theorem guidance, executable formal states, and neural-guided search [2–5, 11, 13, 27]; O MNI -G EO organizes these capabilities around one continually updated typed geometry state.

## 2 Unified geometry state and typed transitions 

Shared formal state. OMNI -G EO instantiates the coupling through a common representation of geometric objects and relations. G EO LIB declares their types, predicates, attributions, and executable theorem schemas. G EO DL represents each problem as (Γ 0, G ): typed input conditions and a typed goal. All three geometry families use one parser, condition store, theorem matcher, equation engine, and goal checker. The compiler first extracts constructions, then conditions from the text and diagram, and finally the goal. Parser feedback and critic-guided repair refine this formalization (Fig. 1), establishing the state on which all subsequent reasoning operates. 

Typed transition contract. To maintain a consistent interface throughout search, we define the state as s = (Γ s, Es, G, Os, Πs): conditions, exact equations, the goal, open obligations, and a provenance ledger. Each candidate is a typed action a = ( τ, η, P, σ ) containing its action class, payload, prior, and source. Candidates from both sources undergo common admission checks for schema, symbols and arity, duplicates, consistency, and direct answer injection. Registered theorem actions are rematched and executed by the engine, with their premise dependencies recorded. Neural constructions or asserted equations can extend the state while retaining open obligations until grounded by input conditions or subsequent exact derivations. Each admitted action is executed on an isolated copy of the parent state under the same transition system: 

s′ = T (s, a ), K(s) = Kthm (s) ∪ K exact (s) ∪ K open ,θ (s). (1) The three action sets correspond to registered theorem application, exact propagation, and open neural extensions. ## 4 Experiments 

Evaluation protocol. We evaluate end-to-end solving on FormalGeo7K (plane; N = 1 ,396 ), Conic10K (analytic/conic; N = 1 ,901 ), and SolidFGeo (solid; N = 1 ,320 ) [28–30]. FormalGeo7K and SolidFGeo use official statement–diagram pairs; Conic10K uses its text input. A prediction is correct only when the engine closes the goal and the external scorer matches the derived answer to the held-out reference. General-purpose baselines use the same available modality and answer normalization; DeepSeek-V4-Flash is explicitly text-only. Within each O MNI -G EO configuration, the compiler and in-search proposer share one frozen backend, while the typed runtime, search policy, and evaluation protocol remain fixed. Appendix C gives complete prompts and budgets. 

Main benchmark results. Table 1 shows that O MNI -G EO improves end-to-end accuracy across all three domains. Relative to direct Claude Sonnet 4.6, the Claude-based system gains 22 .6, 10 .3,and 28 .1 points on FormalGeo7K, Conic10K, and SolidFGeo, raising the macro average from 

70 .5% to 90 .8% (+20 .3 points). Relative to the strongest displayed general-purpose score in each column, the margins are 8.8, 3.9, and 24 .4 points; relative to the strongest complete macro average (GPT-5.4, 77 .7% ), the difference is 13 .1 points. The same runtime and search stack with Qwen3-VL-8B-Thinking reaches 92 .5% , 85 .1% , and 82 .7% (86 .8% macro), showing that the cross-domain result persists under a second neural backend. Where Hilbert-Geo reports comparable entries, the Claude-based system is higher by 10 .0 points on FormalGeo7K and 11 .1 points on SolidFGeo. 

Component analysis. Table 2 changes one component at a time. A fixed source schedule reduces the macro average by 5.1 points; removing neural bridge actions by 19 .3; removing admission filtering by 7.5; and one-pass formalization by 9.6. Every ablation reduces accuracy on every benchmark. The fixed-schedule drop remains tightly grouped at 5.0–5.3 points, while the state-side formalization and admission ablations produce consistent losses, separating the contributions of state construction, transition quality, and adaptive search control.

## 5 Analysis 

State-level composition across geometry families. Equation 1 gives a single transition view of three kinds of progress: registered theorem execution, exact algebraic propagation, and neural bridge actions. They operate over the same typed condition state, so a construction proposed from problem context can immediately create premises for theorem matching, and a symbolic consequence can immediately change the context presented to the neural proposer. The main benchmark profile shows this composition under one parser, condition store, equation engine, and search implementation across plane, conic, and solid geometry. The ablations resolve the corresponding roles: staged formalization determines the quality of the initial shared state, admission controls which proposed transitions enter the tree, neural bridges enlarge the reachable action space, and source allocation determines where expansion effort is spent. 

Search allocation and sensitivity. The outer and inner controllers solve different allocation prob-lems. Source-UCB chooses how to generate the next candidate set at a newly expanded leaf; PUCT then revisits actions that have already entered the tree. This separation is reflected in the fixed-schedule ablation, which changes source allocation while leaving the action interface and traversal rule intact. In the search-constant sweep (Appendix C.5), varying cpuct or cmeta over {0.5, 1.0, 1.5, 2.0, 3.0}

with the other held at 1.5 places the shared setting cpuct = cmeta = 1 .5 at the highest observed accuracy in all three domains; solid geometry is especially responsive to the outer source-allocation constant. This pattern aligns with the consistent gain from adaptive source selection in Table 2. 

Executable semantics as the reusable substrate. The two neural backends change proposal quality and finite-budget solve rate while leaving the geometry state, registered theorem semantics, exact equation execution, and provenance contract unchanged. The Claude and Qwen3-VL-8B-Thinking results therefore exercise the same symbolic substrate with different proposal models. The IMO-AG-30 experiment extends the same design to olympiad construction problems using a compact executable library. Taken together, the experiments position the typed state and transition contract as the stable interface through which model priors, formal deduction, and inference-time search can be composed. 

## 6 Conclusion 

OMNI -G EO formulates geometry reasoning as adaptive search over a shared typed state. Neural guid-ance supplies multimodal formalization, structural proposals, and action priors; symbolic execution supplies registered theorem application, exact propagation, and provenance-aware state updates. The source-UCB/action-PUCT controller repeatedly reallocates computation as this state evolves. Across FormalGeo7K, Conic10K, and SolidFGeo, the resulting system reaches a 90 .8% macro average with Claude Sonnet 4.6 and 86 .8% with Qwen3-VL-8B-Thinking. Component ablations localize gains to staged formalization, neural bridge actions, typed admission, and adaptive source allocation, while the IMO-AG-30 result demonstrates the same interface in an olympiad setting with a compact executable geometry library. Together, these results establish a unified state-level contract for composing learned proposals with exact symbolic execution across heterogeneous geometry domains. 5References

## B Proofs of the Formal Guarantees 

The guarantees distinguish the logical status of a derivation from the search process used to discover it. The statements below retain any open neural dependencies explicitly and specify the conditions under which a returned derivation is grounded. 

B.1 Formal Statements 

We formalize the logical and operational guarantees of the typed transition and search protocol. Registered execution and exact propagation support conditional soundness; state isolation and finite budgets constrain execution; and source allocation and PUCT govern exploration. Let M denote the intended semantics of the compiled signature. The following statements specify these guarantees, with expanded proofs and source-accounting details in the subsequent subsections. 9Assumption B.1 (Certified transition contract). C.3 Input and Evaluation Protocol 

Compiler and search inputs are limited to the benchmark statement and, for multimodal problems, the official raster diagram. The held-out answer y⋆ is accessed by the scorer only after inference. FormalGeo7K and SolidFGeo use their official statement–diagram pairs, whereas Conic10K uses its natural-language statement because its supplied schema contains no raster diagram. The separate IMO-AG-30 study uses the official diagram input. General-purpose baselines receive the same modality as O MNI -G EO on each split. The compiler-generated ˜yθ is stored separately from the benchmark label. Each result record stores the resolved image path or manifest identifier. For the plane and solid multimodal protocols, the runner fails closed if the official image cannot be resolved. Text conditions can populate the image channel only in an explicitly labeled text-only ablation, preventing silent modality substitution in the main evaluation. 

General-purpose baseline inference budget. Each general-purpose language-model baseline uses one semantic model call per problem, with retries reserved for failed calls. Once a valid response is returned, inference terminates; a failed call may be retried up to five times with the identical prompt and decoding configuration, and these retries are not treated as additional independent samples. The maximum completion length is 4096 tokens, temperature is 0, and each individual attempt has a 180-second timeout.
