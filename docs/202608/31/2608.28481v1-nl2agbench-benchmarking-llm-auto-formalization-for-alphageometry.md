## 摘要
近年来，大语言模型（LLMs）的进步展示了其在自然语言理解和数学推理方面的强大能力。然而，它们将非正式的数学问题转化为形式化表示的能力仍未得到充分探索。这一局限性对于诸如 AlphaGeometry 等神经符号几何系统尤为重要，其定理证明引擎需要以专用领域特定语言（DSL）输入。尽管 AlphaGeometry 实现了接近 IMO 金牌得主的性能，但手动将自然语言问题转换为其形式化语法仍然是重大的可用性瓶颈。为了应对这一挑战，我们引入了自然语言到 AlphaGeometry 基准测试（NL2AGBench），用于评估 LLM 将英文几何问题翻译为 AlphaGeometry 兼容的形式化表示的能力。NL2AGBench 利用 AlphaGeometry 内部的基于执行的验证来评估翻译质量，而非仅依赖文本相似性。我们评估了十个跨多种参数规模的先进开源和闭源 LLM，并分析了可执行翻译准确率、语法正确性和错误特征。我们的实验揭示了闭源与开源模型之间的显著性能差距：领先的闭源模型实现了超过 80% 的可执行翻译率，而即使是最大的开源模型也难以持续保留几何约束并生成有效的形式化表示。我们引入了一个区分语法错误和逻辑错误的错误分类法，并研究了几种缓解策略，包括少样本提示、微调和人工引导提示，这些策略在多个模型家族中带来了可衡量的改进。

## Abstract
Recent advances in large language models (LLMs) have demonstrated strong capabilities in natural language understanding and mathematical reasoning. However, their ability to translate informal mathematical problems into formal representations remains underexplored. This limitation is particularly important for neuro-symbolic geometry systems such as AlphaGeometry, whose theorem-proving engine requires inputs in a specialized domain-specific language (DSL). Although AlphaGeometry achieves near-IMO gold-medalist performance, manually converting natural-language problems into its formal syntax remains a significant usability bottleneck. To address this challenge, we introduce the Natural Language to AlphaGeometry Benchmark (NL2AGBench), which evaluates LLMs in translating English geometry problems into AlphaGeometry-compatible formal representations. NL2AGBench uses execution-based verification within AlphaGeometry to assess translation quality rather than relying solely on textual similarity. We evaluate ten state-of-the-art open- and closed-source LLMs across multiple parameter scales and analyze executable translation accuracy, syntactic correctness, and error characteristics. Our experiments reveal a substantial performance gap between closed- and open-source models: leading closed-source models achieve executable translation rates above 80%, while even the largest open-source models struggle to consistently preserve geometric constraints and produce valid formalizations. We introduce an error taxonomy distinguishing syntax and logic errors and investigate mitigation strategies, including few-shot prompting, fine-tuning, and human-guided hinting, which yield measurable improvements across multiple model families.

## 二、方法论

### 1. 基准构建（NL2AGBench）
- **数据来源**：从 Java Geometry Expert（JGEX）仓库中 AlphaGeometry 项目已人工形式化的 **231 个实例**中，筛选出 **48 个代表性几何问题**。
- **筛选标准**：
  - **翻译多样性**：覆盖圆、圆内接四边形、角平分线、垂心、外心、中点、对称、垂直等丰富几何概念；
  - **执行效率**：排除 AlphaGeometry 中运行时间过长或资源消耗过大的问题，保证可规模化评测。
- **基准特点**：每个问题都配有经过验证的正式 DSL 表示，可直接在 AlphaGeometry 中执行——这是与普通数学推理数据集的关键区别。

### 2. 提示策略（Prompting Strategy）
- 向模型提供三类信息：
  - 官方 AlphaGeometry 语法定义；
  - 手写的子句用法与格式约束规则；
  - 目标几何问题文本。
- 要求模型**只输出两行**：标题行（problem_id）+ 定义行（DSL 表示），不输出任何解释或替代方案，模拟真实自动形式化场景。

### 3. 执行验证机制（核心技术创新）
- **不用文本相似度**衡量翻译质量——因为语义上等价的形式化可能在文本上完全不同。
- 采用 **基于执行的验证**：将生成的 DSL 直接交给 AlphaGeometry 执行，根据结果分为三类：
  - ✅ **成功翻译**：可被 AlphaGeometry 接受并成功执行；
  - ❌ **语法错误**：违反 DSL 文法或构造规则；
  - ❌ **逻辑错误**：语法有效但语义与目标几何问题不一致。

### 4. 错误分类体系（Error Taxonomy）
| 错误类型 | 子类别 | 典型特征 |
|---------|--------|---------|
| **语法错误** | Assertion Error | 构造参数数目不正确（如 reflect 缺少定义反射线所需的点） |
| | Key Error | 特殊字符误用、输出变量引用无效、幻觉出 DSL 子句、子句位置错放 |
| | Value Error | 循环定义点、自引用构造、参数数量错误 |
| **逻辑错误** | （无子类） | 省略约束、几何关系错误、目标谓词错误、术语误解 |

### 5. 三种改进策略
1. **少样本提示（Few-Shot Prompting）**：提供 54 个自然语言问题与正确 DSL 翻译的配对示例，帮助模型学习语法与构造模式。
2. **人工引导提示（Human-Guided Hints）**：两阶段纠错框架——第一阶段提供几何图形补充空间信息；第二阶段针对具体错误（如参数数目不对、谓词误用）给出定向修正提示。
3. **监督微调（Supervised Fine-Tuning）**：使用 HAGeo-409（人工验证的几何问题-DSL 配对数据集）微调小规模开源模型。

## 六、主要结论与发现

1. **闭源与开源之间差距悬殊**：
   - 零样本下，GPT-5.4 达 75.00%，Gemini 3.1 达 62.50%；
   - 开源模型中最佳（qwen3:235B）仅为 12.50%，Llama3.1:70B、Llama3.2:3B、Mistral:7B、Nemotron-3 Nano 全部为 **0%**。
2. **少样本提示一致的提升**：
   - Gemini 3.1：62.5% → 83.3%（+21 点）；
   - Qwen3:235B：12.5% → 45.8%（+33.3 点，提升最显著）；
   - Llama3.1:70B：0% → 23%；
   - GPT-5.4：75% → 79.2%（+4 点，闭源中边际收益最小）。
3. **人工提示提升**：GPT-5.4（+14.29%）、Gemini 3.1（+14.63%）、Sonnet 4.6（+26.47%）、Grok-3（+32.14%）。
4. **错误根因**：多数失败源于对 DSL 语法不熟悉（语法错误），而非完全缺乏几何理解；少样本提示对语法错误改善显著。
5. **微调瓶颈**：小模型可学会表层语法模式，但无法可靠捕获几何语义——"看起来对但语义错"仍频繁发生，说明核心瓶颈是推理能力而非语法模仿。
6. **自动形式化可行但未成熟**：前沿闭源模型已可实用，开源模型仍有长路要走。
