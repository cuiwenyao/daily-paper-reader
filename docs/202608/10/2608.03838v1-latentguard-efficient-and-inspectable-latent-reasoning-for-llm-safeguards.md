## 摘要
基于推理的防护模型改进了LLM安全防护，但为每次交互解码显式理由使得部署成本高昂。尽管潜在推理方法通过将推理移动到连续状态来减少token生成，但在安全审核方面仍未充分探索，且缺乏用于部署的检查界面。在本文中，我们提出LatentGuard，一种高效且可检查的安全防护框架，将连续潜在推理引入防护模型。LatentGuard使用分阶段课程逐步将任务对齐的文本理由压缩为紧凑的潜在状态，从而能够直接从连续表示预测安全判定。为了保持可检查性，一个隔离的辅助解码器按需生成紧凑的审计工件，使理由生成脱离标准推理路径。实验表明，LatentGuard-8B在平均加权F1上从83.95提高到84.91，相比于GuardReasoner-8B，同时将关键路径推理成本从268.56个生成的理由token减少到1.60个潜在推理token。其审计解码器实现了85.75的审计效用分数，展示了通往可部署LLM安全防护的高效且可检查的路径。

## Abstract
Reasoning-based guard models improve LLM safeguards, but decoding explicit rationales for every interaction makes them costly to deploy. Although latent-reasoning methods reduce token generation by moving reasoning into continuous states, they remain underexplored for safety moderation and lack an inspection interface for deployment. In this paper, we propose LatentGuard, an efficient and inspectable safeguard framework that brings continuous latent reasoning to guard models. LatentGuard uses a staged curriculum to progressively compress task-aligned textual rationales into compact latent states, enabling safety verdicts to be predicted directly from continuous representations. To preserve inspectability, an isolated auxiliary decoder generates compact audit artifacts on demand, keeping rationale generation off the standard inference path. Experiments show that LatentGuard-8B improves mean weighted F1 from 83.95 to 84.91 over GuardReasoner-8B, while reducing critical-path reasoning cost from 268.56 generated rationale tokens to 1.60 latent reasoning tokens. Its audit decoder achieves an audit utility score of 85.75, demonstrating an efficient and inspectable path toward deployable LLM safeguards.

### 1. 问题形式化

### 2. 分阶段潜在推理课程（Staged Latent Reasoning Curriculum）

- 受 COCONUT 启发，设计三阶段课程（stage s ∈ {1, 2, 3}）：第 s 阶段将前 s 个推理组件替换为潜在 token 序列，其余组件保持文本形式。
- 每个推理组件 c_t 的潜在替换为 **H_t = (h_{t,1}, …, h_{t,m_t})**，采用 COCONUT 风格的连续推理机制——前一隐状态直接作为下一潜在输入（而非查表得到离散词嵌入）。
- 混合推理前缀：**c̃(s) = (H₁, …, H_s, c_{s+1}, …, c₃)**。
- 训练序列：**z(s) = [x; c̃(s); <eor>; v]**，其中 `<eor>` 是推理结束特殊 token，v 是包含三个标签的结构化裁决序列。
- 训练损失为标准下一个 token 预测（式 6），只对剩余文本理由 token、`<eor>` 和裁决 token 计算梯度（排除输入上下文和潜在位置）。
- 课程策略的意图：逐步将显式推理监督压缩进潜在状态，为从紧凑表示直接预测安全裁决提供稳定的训练路径。

### 3. 自适应潜在预算推理（Adaptive Latent Budget Inference）

- 训练用组件对齐的潜在替换，但标准推理采用**统一的自适应潜在前缀**。
- 模型从输入 x 开始循环生成潜在状态 (g₁, …, g_k)，k ≤ K_max。
- 每一步监控 `<eor>` 的概率：**p_eor(k) = p_θ(<eor> | x, g₁, …, g_k)**（式 7）。
- 当 p_eor(k) > τ（默认 τ = 0.7）或达到最大预算 K_max（默认 6）时停止，然后直接生成裁决序列 ˆv 并解析三个标签。

### 4. 潜在条件审计生成（Latent-Conditioned Audit Generation）

- **隔离辅助解码器** D_ψ：仅按需调用，不参与标准推理路径。
- 对每个子任务 t，将守卫模型的潜在序列通过投影器 P_ϕ 映射到解码器嵌入空间（式 9），并应用 **stop-gradient**（防止解码器损失影响守卫模型）。

## 六、论文的主要结论与发现

1. **潜在推理不牺牲审核性能**：LatentGuard 在 1B/3B/8B 三个规模上的三任务平均加权 F1 均超过对应 GuardReasoner 检查点。其中 **LatentGuard-8B 将平均 F1 从 83.95 提升至 84.91**，在请求危害性检测上提升最显著（+1.84 点）。
2. **大幅降低关键路径推理成本**：8B 模型平均推理预算从 268.56 个 CoT token 降至 1.60 个潜在推理 token（约 **168× 压缩**），单样本延迟从 0.792s 降至 0.089s（约 **8.9× 加速**）。
3. **自适应潜在预算有效**：自适应停止（τ = 0.7）在不同难度基准上均能达到饱和性能区域，避免了为所有输入手动选择固定预算的需要；困难基准（如 HarmBenchPrompt）自动分配更多潜在步数。
4. **审计解码器具备实用价值**：LatentGuard-8B 的审计解码器实现 **AUS 85.75**，表明潜在状态可支持按需检查。消融显示源文本锚定和潜在状态两者都重要：去源文本使 AUS 下降 17.14 点，去潜状态也使 AUS 下降。
5. **分阶段课程是有效的训练策略**：去除课程直接训练最终潜在配置会导致 F1 下降（0.38–1.05 点），说明渐进式压缩比一步到位更稳定。
6. **审计工件不是内部推理的忠实重构**：论文明确将审计工件定位为"证据摘要"，而非 faithful explanation，遵循对 CoT 忠实性的审慎立场。

## 七、优点（方法或实验设计上的亮点）

1. **问题定位清晰、角度新颖**：将"效率–性能–可检查性"三角明确形式化，并提出"解耦预测与理由生成"这一务实的设计哲学，对部署场景有直接指导意义。
2. **方法设计巧妙**：
   - 分阶段课程从显式推理监督平滑过渡到潜在计算，解决直接潜在训练不稳定的问题；
   - 训练（组件对齐潜在替换）与推理（自适应潜在前缀）的有意分离，兼顾监督效果与推理效率；
   - 审计解码器使用 stop-gradient 和隔离设计，保证审计训练不干扰守卫模型的潜在推理动态。
3. **评估体系完整**：将"审计效用"作为独立评估维度，并提出 Verify F1 / Accept. Rate / AUS 三项指标；引入 386 条人工标注验证自动评估的一致性，提高了审计评估的可信度。
4. **控制实验严谨**：w/o curriculum 和 w/o latent 两种消融对照，有效排除了"单纯额外训练带来增益"的混淆解释。
5. **统计报告规范**：主结果报告三随机种子均值 ± 标准差，附录提供全量分项基准结果，透明度高。
6. **坦诚的定位**：明确审计工件非忠实解释、需配合源交互使用，避免了对可解释性的过度承诺。

## 八、不足与局限

1. **审计模式仍有额外计算开销**：虽然理由生成不在标准推理路径上，但当审计模式被请求时（如抽样审查、高风险案例）仍会增加计算消耗；若每个决策都需审计，则效率优势会被削弱。论文在 Limitations 中承认了这一点。
2. **审计工件非忠实内部解释**：解码器生成的是紧凑证据摘要，而非守卫模型内部计算的因果重构，可能与真实推理过程存在偏差；应结合源交互和预测标签一同解读。
3. **评估范围限于文本**：仅覆盖 GuardReasoner 形式化框架下的文本安全审核，未涉及多模态输入、长对话、动态安全策略等更复杂场景。
4. **GPU 型号未披露**：训练资源描述不完整（未说明 GPU 型号），影响算力绝对量级的准确评估与复现参考。
5. **审计评估的人工验证规模有限**：386 条人工标注样本虽体现较高一致性，但样本量相对较小，且未详细描述标注者背景和标注者间一致性（仅报告人机一致性），可能存在单标注者偏差。
6. **与部分基线的比较受限**：LlamaGuard 在拒绝检测任务上无法参与比较，导致三任务均值比较中其缺席，削弱了与最新分类基线的全面可比性。
7. **训练数据依赖合成数据**：GuardReasonerTrain 由多个来源合成，可能存在标签噪声和分布偏差；安全策略的时效性（论文日期为 2026 年 8 月）也意味着策略演进后的泛化能力未验证。
8. **潜在推理的可控性**：潜在状态的解释性天然弱于显式文本，虽通过审计解码器弥补，但当审计生成失败时（图 6 右例展示了误判案例），错误分析的困难程度高于显式推理方法。
