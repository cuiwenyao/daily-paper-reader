## 摘要
使用大型语言模型（LLM）和检索增强生成（RAG）回答复杂条件问题仍然是一项挑战，尤其是在通用LLM和RAG往往表现不佳的特定领域场景中。我们假设，通过将RAG与从文档和知识图谱（KG）中提取的非结构化及结构化知识相结合，可以提升此类任务的推理能力和答案准确性。为验证这一假设，我们提出了KGCaRe，一种将神经检索与基于LLM生成的知识图谱上的符号推理相结合的混合方法。KGCaRe使用多提示词提取策略从文档中构建知识图谱，并将其存储在图数据库中。同时，文档被嵌入到向量存储中以实现神经检索。KGCaRe采用创新的迭代图遍历方式，由LLM引导提取相关三元组、剪除无关信息，并在初始遍历未能提供足够上下文生成答案时，利用额外的线索实体再次遍历图谱。从知识图谱中提取的相关路径形式三元组，与语义检索的文本段落一起，被输入到定制的KGCaRe提示词中，以生成复杂条件问题的带解释答案。我们在两个复杂条件问答数据集上评估了KGCaRe。实验结果表明，在Mistral、Mixtral、GPT-3.5和GPT-4o等多种LLM上，KGCaRe持续优于现有基线方法，包括Vanilla LLM、Code Prompt、Text Prompt、Think-on-Graph、Vanilla RAG和HybridContextQA。我们公开发布了用于实现所提出的KGCaRe方法的软件流程。

## Abstract
Answering complex conditional questions using Large Language Models (LLMs) and Retrieval-Augmented Generation (RAG) remains a challenge, particularly in domain-specific contexts where general-purpose LLMs and RAG tend to underperform. We hypothesize that augmenting RAG with unstructured and structured knowledge, extracted from both documents and knowledge graphs (KGs), can improve reasoning and answer accuracy for such tasks.   To test this, we propose KGCaRe, a hybrid approach that combines neural retrieval with symbolic reasoning over LLM-generated KGs. KGCaRe constructs a KG from documents using a multi-prompt extraction strategy and stores it in a graph database. Simultaneously, the documents are embedded into a vector store to enable neural retrieval. KGCaRe performs innovative iterative graph traversal guided by the LLM to extract relevant triples, prune irrelevant information, and uses additional clue entities to traverse the graph again if the initial traversal does not provide satisfactory context to generate the answer. The relevant triples extracted from the KG in path form, along with semantically retrieved text passages, are then fed into custom KGCaRe prompts to generate answers to the complex conditional questions with explanations.   We evaluate KGCaRe on two complex conditional QA datasets. Our results on these datasets show that KGCaRe consistently outperforms existing baselines, including Vanilla LLM, Code Prompt, Text Prompt, Think-on-Graph, Vanilla RAG, and HybridContextQA, across multiple LLMs such as Mistral, Mixtral, GPT-3.5, and GPT-4o. We publicly release the software pipeline that we developed to implement the proposed KGCaRe approach.

## 2. 论文提出的方法论：核心思想、关键技术细节、算法流程

**方法论名称**：KGCaRe（Knowledge Graph Context aware Reasoning for complex Question Answering）

- **核心思想**：构建一个混合检索增强问答系统，将**符号推理（知识图谱遍历）** 与**神经检索（向量语义搜索）** 相结合，通过LLM引导的迭代图遍历与剪枝，融合结构化和非结构化上下文生成答案。
- **技术架构与流程**：
  1. **多提示词三元组抽取与KG构建（Multi-Prompt Triple Extraction）** ：
     - 使用四阶段渐进式提示策略从文档中提取高精度的（subject, predicate, object）三元组；
     - 阶段一：上下文理解与初始实体-关系抽取，强调时序、因果、程序、条件结构；
     - 阶段二：条件与替代场景扩展，显式捕捉if-then结构、例外与替代逻辑；
     - 阶段三：细化与逻辑图扩展，基于传递性和蕴含逻辑推导新三元组；
     - 阶段四：输出规范化并导入Neo4j图数据库。
  2. **语义向量索引**：文档同时用LLM嵌入器转为高维向量，存入FAISS索引，支持近似最近邻检索。
  3. **KG遍历（算法1为核心）** ：
     - 使用LLM从输入问题中抽取主题实体（Etopic）作为起始锚点；
     - 在深度限制D内迭代遍历：第一层用部分匹配，后续层用精确匹配；
     - 引入**线索实体（clue entities）** 机制，当已有上下文不足以回答问题时，由LLM建议新的搜索实体以扩展遍历广度；
     - 每轮遍历后使用LLM对三元组进行剪枝（PruneTriples），过滤无关信息；
     - 维护三元组记忆M、线索实体记忆、遍历路径记忆，并在每层判断上下文是否充足，不足则继续遍历或触发fallback模式；
     - 最终将KG路径三元组与向量检索结果融合进定制提示词生成答案。
  4. **融合检索与答案生成**：将KG遍历得到的三元组路径与FAISS返回的top-k文本段落解析到同一提示词中，要求LLM结合两种证据生成答案，适用于需要显式条件说明的问题，提高了可解释性和事实一致性。

## 6. 论文的主要结论与发现

1. **混合架构有效**：在所有LLM和数据集上，KGCaRe的平均F1始终优于全部6类基线，验证了“符号KG推理 + 神经向量检索”融合范式的有效性；
   - 例如：Mistral在ConditionalQA上Avg F1为57.89（HybridContextQA为45.17）；GPT-4o在ConditionalQA上为67.55（HybridContextQA为63.71）；GPT-4o在HotpotQA上Avg F1达80.21。
2. **小模型获益更大**：Mistral和Mixtral等开源模型从KG遍历与上下文融合中获得的相对增益最显著，表明混合检索可以弥补弱模型的推理短板；
3. **条件问题增益明显**：KGCaRe在Conditional类型上的提升最为突出（如Mistral下Conditional F1 = 57.17，远高于Vanilla RAG的21.11和HybridContextQA的34.39），说明显式条件建模的重要性；
4. **KG-only方法局限明显**：Think-on-Graph在所有模型上表现最差（在多个配置下接近0），说明仅依赖KG的推理在真实复杂文档场景中难以奏效；语义检索的鲁棒性是必要的补充；
5. **强势LLM也受益**：即使在GPT-4o这类高容量模型上，KGCaRe的混合上下文仍带来一致但幅度较小的提升，说明符号化辅助信息具有补缺而非替代作用；
6. **可解释性**：KGCaRe可以显式追踪遍历路径与剪枝过程，提供人类可理解的推理链和条件说明，提升透明度与可信度。

## 7. 优点

## 8. 不足与局限

- **实验覆盖不足**：
  - KG构建质量未做专门评估（无人工评测三元组精确率/召回率），无法判断KG质量问题对最终效果的影响边界；
  - 未考察不同KG深度D、top-k等超参数对性能的敏感性；
  - 缺少统计显著性检验（如重复运行 + 配对显著性测试），无法排除随机性因素；
  - 对不同类型的RAG框架（如Blended RAG、GraphRAG变体）未做更全面的横向比较；
  - HotpotQA上仅使用500个QA的子集，且只覆盖Yes/No和Span两类，未覆盖更广的复杂问题形态。
- **偏差风险**：
  - 使用了4个few-shot示例来自训练集，对不同问题类型可能产生选择偏差；
  - LLM自身作为KG抽取器与推理器的双重角色，存在错误传播风险——KG中的噪声三元组可能被剪枝遗漏并进入最终答案；
  - 对GPT-3.5/4o使用的温度等解码参数与开源模型不同，跨模型对比的公平性有一定限制；
  - 未提供多次实验的方差信息，无法判断改进的稳定性。
- **应用限制**：
  - 多阶段提示词KG构建流程计算成本高，更新频率低时适用，但对实时性要求高的场景适配性有限；
  - 依赖LLM的抽取质量，在低资源领域或罕见实体上可能表现不稳定；
  - KG构建与遍历的复杂度随文档规模呈现非线性增长，扩展性未在更大语料上验证。
