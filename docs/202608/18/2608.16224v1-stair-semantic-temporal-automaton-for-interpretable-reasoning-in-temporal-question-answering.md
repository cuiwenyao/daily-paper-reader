## 摘要
通过利用大规模预训练，LLMs能够在无需任务特定训练的情况下解释多样化的时间表达和问题表述。然而，现有的基于提示的神经符号系统仍然依赖LLMs进行语义解释和精确的时间推理。因此，关于区间、时间锚点和有序状态的离散决策仍然容易受到概率性错误的影响，并且难以验证。我们提出了STAIR，一种用于可解释推理的语义-时间自动机。STAIR将语义解释与精确的时间推理分离：一个与答案无关的LLM适配器将复杂的问题表述映射为归一化的时间意图，而一个具有有限控制和保护转换的确定性时间自动机在规范化证据上执行相应的策略。遵循规则优先的设计，STAIR在不调用LLM的情况下解决标准问题，并且仅在规则路径未能生成可执行意图时应用语义适应。这种方法减少了自由形式的推理，使时间决策可验证且可解释。具体而言，保护执行支持精确的时间点包含和之前/之后选择，而语义适应处理非精确区间和时间锚定查询。在TimeQA-Easy、TimeQA-Hard、TempReason-L2和TempReason-L3数据集上，STAIR在使用匹配模型设置下始终在TQA任务中优于强基线，利用Qwen2.5-7B和GPT-4o-mini模型时分别实现了16.57%和3.10%的平均F1改进。此外，消融和诊断分析表明，STAIR在处理边界敏感和顺序敏感的查询方面表现出色，而其保护执行和语义适应分别确保了精确的时间点推理和非精确区间。

## Abstract
By leveraging large-scale pretraining, LLMs can interpret diverse temporal expressions and question formulations without task-specific training. However, existing prompt-based neuro-symbolic systems continue to rely on LLMs for both semantic interpretation and exact temporal inference. Consequently, discrete decisions regarding intervals, time anchors, and ordered states remain vulnerable to probabilistic errors and difficult to verify. We present STAIR, a \textbf{S}emantic-\textbf{T}emporal \textbf{A}utomaton for \textbf{I}nterpretable \textbf{R}easoning. STAIR separates semantic interpretation from precise temporal inference: an answer-free LLM adapter maps complex question formulations to normalized temporal intents, while a deterministic temporal automaton with finite control and guarded transitions executes the corresponding policies over canonicalized evidence. Following a rule-first design, STAIR resolves standard questions without invoking an LLM and applies semantic adaptation only when the rule path fails to produce an executable intent. This approach reduces free-form reasoning, making temporal decisions verifiable and interpretable. Specifically, guarded execution supports precise point-time containment and before/after selection, while semantic adaptation handles non-exact intervals and time-anchored queries. Across the TimeQA-Easy, TimeQA-Hard, TempReason-L2, and TempReason-L3 datasets, STAIR consistently outperforms strong baselines in the TQA task using matched model settings, achieving average F1 improvements of 16.57\% and 3.10\% when utilizing the Qwen2.5-7B and GPT-4o-mini models, respectively. Furthermore, ablations and diagnostic analyses demonstrate that STAIR excels at handling both boundary-sensitive and order-sensitive queries, while its guarded execution and semantic adaptation ensure precise point-time reasoning and inexact intervals, respectively.

## 1. 核心问题与整体含义

**研究动机与背景**：时间问答（TQA）要求模型在时间索引的证据上进行推理，既需要理解多样化的自然语言时间表达（如“between Jul 1997 and Sep 1997”），也需要对时间排序的证据进行精确的离散选择（如边界对齐的区间匹配、点-区间包含、前驱/后继选择）。现有提示式神经符号系统（如 NeSTR、TISER）虽然引入中间表示和推理轨迹，但**仍依赖 LLM 同时进行语义解释与精确时间推断**，导致离散的时间决策（区间边界、时间锚点、有序状态的选择）易受概率性错误影响，且难以验证——即使推理链表面连贯，仍可能选错区间边界或过选/漏选前后状态。

**核心洞察**：论文通过路由分析发现，大多数时间问题（TimeQA-Easy 中 76.91%、TempReason-L2 中 76.91%、TempReason-L3 中 91.46%）在事实与算子规范化后可直接由确定性执行解决；仅 TimeQA-Hard 因包含大量非精确区间、时间值锚点等复杂表达，规则覆盖仅为 27.65%。因此，**LLM 干预的主要需求在于解释非规范时间表达和推断意图，而非替代每一个时间决策**。

## 2. 方法论

**核心思想**：STAIR（Semantic-Temporal Automaton for Interpretable Reasoning）遵循 **“LLM 作为解析器，自动机作为推理器”**（LLM-as-parser, Automaton-as-reasoner）的规则优先（rule-first）架构，将**语义解释与确定性时间执行分离**。LLM 仅在规则路径失败时被引入，且只做语义归一化，不能选择证据或生成最终答案；离散时间决策全部由确定性时间自动机完成。

**系统组成与流程**：

1. **规范事实构建（Canonical Fact Construction）**：将时间上下文规范化为 `(s, r, o, t_s, t_e)` 形式的事实元组。结合确定性规则解析（处理半结构化记录和句模板）与受约束的 LLM 符号解析，规范化时间值、拒绝不完整记录、按规范化键合并事实并保留来源元数据。

2. **规则优先执行（Rule-First Principle）**：对可直接识别的算子（如 `from t1 to t2`、`in t`、`before entity`、`after entity`），直接将问题映射为可执行意图，无需调用 LLM。LLM 不能覆盖成功的确定性结果。

3. **硬结构检测器（Hard-Structure Detector）**：规则执行失败后，识别需要语义归一化的困难案例（非精确区间、时间值前后锚点、未解析日期格式等），避免不必要的 LLM 调用。

4. **语义适配器（Semantic Adapter）**：对困难问题，LLM 接收问题与规范事实，输出**与答案无关的结构化意图** `(type, subject, relation, anchor, policy)`，支持 `interval`、`point`、`before_anchor`、`after_anchor`、`first`、`last` 六种意图类型。适配器**不能输出答案**，防止答案泄漏。

5. **程序验证与规范化（Program Validation and Normalization）**：对适配器输出进行模式检查、时间参数检查、目标键检查和事实准入检查，拒绝非支持意图、缺失时间参数、非法日期和类答案内容。

6. **时间自动机选择器（Temporal Automaton Selector, TAS）**：形式化为带守卫的扩展有限状态机 `M = (S, Ξ, δ, S0, Sterm)`，状态 `S0→S1→S2→S3→S4→S5` 依次对应事实验证、意图验证、事实组选择、策略执行、答案聚合；任一步守卫失败则进入带类型失败原因的 `S⊥` 状态，触发语义修复或最终回退。

7. **时间策略（Temporal Policies）**：
   - **精确区间**：边界完全对齐匹配；
   - **非精确区间**：最大重叠长度计算 `ω(f, q) = max(0, min(t_ef, q_e) − max(t_sf, q_s))`，保留重叠最大的事实；
   - **点时间**：包含关系判断 `t_sf ≤ q_t ≤ t_ef`；
   - **实体锚定 before/after**：选取锚定事实的最近前驱或后继；
   - **first/last**：选择时间链上最早/最晚事实。

8. **直接答案发射（Direct Answer Emission）**：从选定对象跨度直接复制答案，防止无依据实体和表面形式改变。仅当语义修复与确定性重选均失败时，才调用 4 阶段 LLM 回退（符号表示→时间推理→一致性检查→反思/最终答案）。

## 6. 主要结论与发现

1. **分离语义解释与确定性时间推理可以显著提升 TQA 表现**：STAIR 在全部 4 个模型上超越 NeSTR，平均 F1 提升 2.78~12.71 点，EM 提升 5.96~17.08 点；在使用 Qwen2.5-7B 和 GPT-4o-mini 时分别实现 16.57% 和 3.10% 的平均 F1 改进（见摘要）。

2. **大幅降低对底层模型容量的敏感性**：STAIR 在不同模型间的平均 F1 方差仅 3.07 点，而 NeSTR 为 13 点，表明确定性执行减少了对 LLM 规模和质量的依赖。

3. **边界敏感与顺序敏感查询均受益**：TempReason-L2/L3 上的平均 F1 提升（9.48/9.62 点）高于 TimeQA-Easy/Hard（1.89/3.08 点），因为前者主要包含可直接映射到确定性策略的点包含和 before/after 查询。

4. **LLM 仅需负责语义归一化而非时间决策**：语义适配器将 TimeQA-Hard 上 F1 从 72.75 提升到 80.91，并将最终回退率从 72.35% 降至 37%。

5. **规则优先设计带来显著效率优势**：在结构规整的数据集（TimeQA-Easy、TempReason-L2/L3）上大幅减少 LLM 调用（TempReason-L3 从 1 降至 0.21）、token 使用和时间消耗；但在困难约束（TimeQA-Hard）上因额外适配与修复而花费更多计算。

6. **过程可解释性**：确定性自动机为每个实例暴露规范事实、归一化意图、激活策略、守卫结果、所选证据和答案来源，推理轨迹反映了实际计算而非事后生成的自然语言。

## 7. 优点

1. **清晰的职责划分**：将 LLM 限制在语义归一化，将时间计算交给确定性自动机，在原理上消除了概率性错误对离散时间决策的影响。

2. **规则优先架构**：大多数问题无需调用 LLM 即可解决，兼顾准确性与效率；LLM 调用按需触发且有严格约束。

3. **过程可解释性**：有限状态机 + 守卫转换的结构使每次预测都可审计，支持失败原因的定位与修复，而非事后合理化。

4. **防答案泄漏设计**：语义适配器与答案无关，通过模式验证和校验拒绝类答案输出，确保最终时间选择由确定性策略完成。

5. **跨模型稳健性**：在不同规模的开源和闭源模型上表现一致，模型间方差极小。

6. **充分的消融与诊断设计**：组件消融、执行器消融、按问题类别诊断、跨源迁移和效率分析从多个角度验证了设计动机和贡献来源。

## 8. 不足与局限

1. **时间粒度不匹配导致的边界错误**：如附录 H.3 所示，当月级查询落在共享年份边界内时（如“Feb 1908”与“1908–1912”区间），TAS 的闭合区间比较将查询映射到前一区间，而黄金注释将其视为有效。这是系统性的确定性边界缺陷，非偶发错误，在多个骨干模型上均出现。

2. **策略库存有限**：尚未支持高度隐式事件排序、时长比较、否定、嵌套约束、多跳时间组合等现象，超出当前策略清单的问题最终交由 LLM 回退，但这些预测**缺乏 TAS 的守卫级执行轨迹**，失去过程可解释性。

3. **事实规范化瓶颈**：上下文若难以转换为规范事实（如实体字段缺失、时间边界不可解析），无法进入确定性执行路径，影响覆盖范围。

4. **CronQuestions 评估覆盖有限**：仅覆盖算子支持的转换子集（13,096/30,000），不含 time-answer 类型、time join 类型和一般逆时间线，不能作为完整 CronQuestions 基准性能的代表。
