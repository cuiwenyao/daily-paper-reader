## 摘要
我们提出了RuleChef框架，该框架利用大语言模型（LLM）为文本分类、命名实体识别（NER）或关系抽取等自然语言处理任务生成可执行的规则。规则基于任务描述和一组带标签的示例生成，然后通过额外的示例以及人类对现有规则的反馈进行迭代改进。RuleChef还可以通过利用给定任务任何现有模型观察到的输入-输出对来引导规则。LLM仅在训练时使用，用于合成规则并根据在保留集上测量的失败进行迭代修补。该过程的结果是一个快速、确定性和可检查的规则系统。我们在分类和NER任务上进行了初步评估。我们以Apache 2.0许可证将RuleChef作为开源软件发布。

## Abstract
We present RuleChef, a framework that uses large language models (LLMs) to generate executable rules for NLP tasks such as text classification, Named Entity Recognition (NER), or relation extraction. Rules are generated based on a task description and a set of labeled examples, then they are iteratively improved based both on additional examples and on human feedback overexisting rules. RuleChef can also be used to bootstrap rules using the observed input-output pairs from any existing model for a given task. LLMs are used only at learning time, synthesizing rules and iteratively patching them based on failures measured on a held-out split. The result of this process is a fast, deterministic, and inspectable rule system. Preliminary evaluation is performed on both classification and NER tasks. ## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：现代NLP系统多依赖黑箱模型（如深度神经网络、LLM），预测缺乏可解释性、不可审计、难以调试，且推理成本高。而在医疗、法律、金融等敏感领域，可追溯、可编辑、确定性的规则系统更受青睐，但手动编写规则耗时耗力且需要领域专家。
- **研究动机**：利用LLM的生成能力，自动将任务知识（从标注示例、人类反馈或现有模型行为）转换为可执行、可编辑的符号规则，从而在推理时完全脱离LLM，实现快速、确定、可检查的规则系统。
- **整体含义**：RuleChef提出“学习时用LLM，推理时只用规则”的范式，将LLM作为规则生成器而非推理器，在保证性能的同时极大提升可解释性、可控性和计算效率。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：RuleChef是一个迭代式规则学习框架。给定任务描述和少量标注示例，LLM首先生成初始规则（支持正则表达式、spaCy模式、Python代码）；然后在保留开发集上评估规则，聚类失败模式，驱动LLM修补规则；修补仅当开发集F1不下降时才接受；最后通过冲突解决和剪枝得到最终规则集。
- **关键技术细节**：
  - **规则合成**：针对每个类别生成单独规则，避免跨类干扰。提供grex（自动正则生成器）产生的模式提示，帮助LLM发现结构规律。
  - **迭代修补**：每次修补时，将失败样例按类型（遗漏、误报等）聚类，采样后与当前规则及指标一起输入LLM，LLM可修改、新增或删除规则。
  - **接受标准**：仅当修补后开发集F1不下降或精度提升时才保留，防止过拟合。
  - **冲突解决**：当多个规则重叠时，按优先级（可配置）和开发集精度（经Wilson下限修正）决定最终输出；再通过留一法去除边际贡献为负的规则。
  - **人类反馈**：用户可以针对特定规则给出自然语言反馈（如“不要匹配xxx”），该反馈被注入后续修补提示中。
  - **观察模式**：在无标注数据时，RuleChef可从外部LLM的输入-输出对中学习规则。先通过任务发现提示推断任务模式，再映射观测数据为训练样例，然后启动规则学习。
  - **智能协调**：可选智能体（Agentic Coordinator）在每次迭代后分析各类指标，生成指导策略；规则审计员合并冗余规则；规则评论员给出整体建议。所有变化需通过开发集验证。
- **算法流程（文字描述）**：
  1. 输入：任务定义、标注示例/反馈/观测数据；划分训练集和开发集。
  2. 初始规则合成：对每个类别，用包含正例和反例的提示让LLM生成一组规则。
  3. 评估规则：在开发集上计算精召F1，记录每个规则精度和匹配数。
  4. 失败聚类与修补：识别失败模式，采样失败样例，连同当前规则和人类反馈构造修补提示，LLM输出规则更新。
  5. 接受检查：若新规则集在开发集上不降低，则接受；否则回退。
  6. 冲突解决与剪枝：排序规则、合并重叠、删除无用规则。
  7. 输出最终规则系统（仅规则，无LLM）。

## 6. 主要结论与发现

- **主要结论**：RuleChef能自动生成高精度的可编辑规则系统，在格式类实体上超越LLM提示和GLiNER2（89.1%精确率 vs 65-70%），在语义类实体上精确率最高（75.7%），但召回率较低（47.8%）。整体规则系统性能高于底层RoBERTa NER，但低于微调长文former。
- **关键发现**：
  - 迭代修补+开发集验证是提升性能的核心（消融实验：从一次性规则的7.4%语义F1提升到44.4%）。

  - 智能协调有助于减少规则数量（从36条减至9条）而不明显损失F1。
- **对实践的意义**：RuleChef特别适合需要高精度的敏感领域，可作为混合系统的第一级，提高可解释性和降低计算成本。
