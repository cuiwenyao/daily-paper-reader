## 摘要
神经符号研究通常假设存在一个预先给定的符号规范，因而在很大程度上未解决获取并形式化需求与约束这一上游挑战。我们提出一种架构，通过使用 OWL 配置本体在神经约束来源与下游消费者之间进行中介，从而填补这一空白。在该框架中，LLM 助手引出软性的利益相关者偏好，而硬件规范则定义硬性的物理与工程限制。该本体统一这些异构输入，利用描述逻辑识别不可满足性，并生成符号解释，使 LLM 能够与用户交互式地重新协商条款。任何剩余冲突都在下游通过基于优先级的松弛来解决。我们以 FLEXI 项目中的微电网用例说明该方法，并论证其可推广到多利益相关者领域，在这些领域中，约束获取分布在权威性不等的人类与自动化来源之间。

## Abstract
Neurosymbolic research typically assumes a pre-existing symbolic specification, leaving the upstream challenge of acquiring and formalizing requirements and constraints largely unaddressed. We present an architecture that fills this gap by using an OWL configuration ontology to mediate between neural constraint sources and downstream consumers. In this framework, LLM assistants elicit soft stakeholder preferences, while hardware specifications define hard physical and engineering limits. The ontology unifies these heterogeneous inputs, leverages description logic to identify unsatisfiability, and generates symbolic explanations that enable LLMs to interactively renegotiate terms with users. Any remaining conflicts are resolved downstream via priority-based relaxation. We illustrate our approach on a microgrid use case from the FLEXI project and argue its generalizability to multi-stakeholder domains where constraint acquisition is distributed across human and automated sources of unequal authority.

- **被忽视的上游问题**：现有神经符号（neurosymbolic）研究绝大多数聚焦"下游"——即假设符号规范（specification）**已经存在**，只关注如何让神经输出满足该规范（约束解码、符号验证器、定理证明器等）。而"这些符号规范本身如何被获取与形式化"这一**上游问题**基本空白。
- **真实场景中的约束是异构且冲突的**：
  - 约束并非固定，也不来自单一权威，而是从多个异质来源**获取并拼装**而成。
  - **硬约束**：来自硬件规格的物理与安全限制，不可协商（如保险丝容量、变压器容量、电池安全参数、灵活性市场承诺如日前投标）。
  - **软约束/偏好**：来自多个利益相关者的自然语言对话式需求，彼此可能冲突，且**权威性不等**（例如电网运营商的电网稳定性要求优先于单个用户的偏好）。
- **核心矛盾**：在规范可用之前，必须先把这些来源**调和（reconcile）为单一一致的约束集**，并检测与消解冲突。作者主张**配置本体（configuration ontology）**是承担这一中介角色的理想层次。
- **技术出发点与缺口**：基于 Siemens 的 **CONTO**（基于 OWL 的供应商无关产品配置本体），它已提供组件/特性/约束的标准表示与描述逻辑一致性检查，但**只支持硬约束**——没有偏好、优先级、优化目标的概念。补齐这一点正是多利益相关者约束获取的核心诉求。
- **用例背景**：FLEXI 项目中的微电网（含光伏、固定电池、EV 充电桩），需在可持续性、电网稳定性、成本之间做充放电调度。

## 2. 方法论

### 2.1 核心思想

- 在**约束来源**与**下游消费者**（FLEXI 中的调度器）之间插入一个**配置本体作为中介层**（Figure 1）。
- 来源分两类：① 面向人类利益相关者的 **LLM 助手**（对话式引出软偏好）；② **硬件规格**（直接注入硬性物理限制，不经引出、永不松弛）。
- 本体负责：把异构输入**形式化为统一表示** → 打上 hard/soft 标签与优先级 → **静态可满足性检查** → 生成**符号解释**回传 LLM 助手 → 助手与用户**重新协商** → 剩余冲突交下游按优先级松弛。
- 关键主张：把偏好建模为**一等的、带权、可松弛约束**（而非带外评分函数），使其与硬限制共享同一形式表示，从而**同一套可满足性检查与冲突解释同时适用于两者**。

### 2.2 关键组件与技术细节

- **CONTO 三层结构**：L2 通用元模型（组件、特性、约束词汇）／L1 产品线（针对 L2 定义可配置工件）／L0 具体配置实例。
- **两套互补形式化**：
  - **ConfigVoc（`cv:`）**：基于实例的 **OWL 2 QL** 词汇，约束被**物化（reified）为数据**——表格约束（行/单元格）或公式约束（表达式树）。
  - **ConfigDL（`cdl:`）**：基于类的形式化，约束即 **OWL 公理**，由 DL 推理机通过一致性检查原生执行。
  - 两者原本**全部约束都是硬的**，无偏好、无优先级、无优化目标。
- **提出的偏好扩展（`pref:` 词汇）**：
  - `pref:constraintType`（Hard / Soft）；
  - `pref:priority`（数值优先级，软约束另可选权重）；
  - `pref:PreferenceAggregate`（把某利益相关者的软约束聚为一组，供下游尽量满足）。
  - 语义借鉴 **valued CSP / semiring-based CSP** 与 **ASP 的 weak constraints**：违反硬约束 → 集合不可行；未满足软约束 → 非"违反"而是"松弛"，产生正比于优先级的**违反代价**。
  - Listing 1 示例：`flexi:fuseCapacity` 为硬约束（`sumChargerPower <= fuseCapacity`）；`flexi:desiredSOC` 为软约束（`actualSOC >= targetSOC`，priority 1000），并归入 `flexi:evOwnerPreferences` 聚合。
- **两类冲突的检查路径**（关键工程细节）：
  - **结构冲突**：偏好与产品模型或硬约束在本体层矛盾（如请求被禁选项）→ 由**描述逻辑推理**判定。
  - **数值冲突**：偏好直接违反数值边界（如向 60 kWh 电池充 90 kWh）→ DL 无法判定，需要**对公式约束的算术推理**。
  - 若扩展寄宿于 **ConfigDL**：OWL DL 推理机处理结构冲突，**DL-safe SWRL 规则 + 算术内建**在**已接地（grounded）值**上检查数值公式约束（对开放变量的可行性超出其能力），检查保持在 OWL 内，但可松弛约束在 OWL 全有全无的公理语义下"没有天然的归宿"。
  - 若寄宿于 **ConfigVoc**：公式约束可导出到 **MiniZinc**（CONTO 已提供该路径）做数值检查，并把物化约束聚合为**加权目标**，为软约束语义提供天然落点；**ASP** 是另一转换目标，可直接把优先级实现为带 weight/level 的 weak constraints。
- **解释（justification）机制**：偏好未通过检查时，返回**导致冲突的最小硬约束集合**——Pellet/Openllet 计算不一致的最小公理/规则集，MiniZinc 报告数值约束的**最小不可满足子集（MUS）**。作者强调这是选型标准：**只给判定、不给冲突集的工具无法驱动该循环**。返回结果是**共享词汇表中的具名约束**（非自由文本），以结构化 tool-call 结果交回助手。

### 2.3 流程（文字化算法）

1. LLM 助手在自然语言对话中引出某利益相关者的偏好；
2. 助手把开放式话语**接地**为共享词汇表上的带类型约束，写入本体；
3. 本体分类 hard/soft、附加优先级，并纳入偏好聚合；
4. **静态可满足性检查**：把候选软偏好**当作硬约束**，对硬约束集测试（不与其他软偏好互测）；
5. 若失败 → 生成最小冲突集 justification → 回传原助手 → 助手向用户具名呈现冲突约束、重新协商 → 修订后的约束重新入环（迭代直至静态可行）；
6. 采集是**持续**而非一次性的：约束可随时到达或变更，每当可行集变化就**重新调用调度器**；
7. 第二处松弛发生在**调度器**：结构一致的集合仍可能在规划时域上联合不可满足，此时按优先级/权重决定松弛哪些软约束及松弛幅度，以最小化总违反代价并保持硬约束；
8. 调度结果经同一助手回馈用户，在"已实现日程"层面**第二次闭环**。
9. **重要设计取舍**：软偏好之间**故意不互相测试**——每个都可松弛，任意两者都不构成不可满足，因此"两者相争谁让步"是**优先级问题而非一致性问题**，交给调度器。

## 6. 主要结论与发现

- **将"多利益相关者约束获取"框定为独立的神经符号问题**，是已被充分研究的下游验证任务的必要补充。
- 提出**本体介导的架构**：LLM 助手（软偏好）+ 硬件来源（硬限制）→ OWL 配置本体统一表示；通过**扩展 hard/soft 区分与优先级**，用户偏好成为可松弛的加权约束，与硬物理限制并存。
- 描述了**闭环神经符号回路**：描述逻辑推理检测结构冲突并返回**符号解释**，驱动助手与用户重新协商；剩余冲突由下游**基于优先级的松弛**解决。
- 明确**两处松弛点的分工**：静态检查负责"个体可满足性"（结构 + 数值），调度器负责"联合/资源可行性"（多目标、按代价最小化松弛）。
- **可推广性论证**：架构不依赖能源领域。结构同构的例子是**多租户楼宇气候控制**——租户通过各自助手表达舒适偏好（软），设施经理给出楼宇能耗上限与安全要求（高权威），设备数据表固定执行器与厂站限制（硬）；租户为同一受限供给竞争，正如 EV 车主争夺变压器容量。
- **研究议程**：确定偏好语义寄宿于 ConfigVoc 还是 ConfigDL、建立跨群体优先级语义与多目标处理、保证忠实接地与交互时间内的推理；**偏好扩展的首个原型是下一步**。

## 7. 优点

- **问题框定有真实价值**：指出神经符号社区"默认符号规范已存在"的系统性盲区，把约束获取/形式化提升为独立问题，并抓住"**权威不等的多来源 + 异构 + 冲突**"这一现实中普遍但少被建模的特征。
- **表示层面的关键设计**：把偏好做成**一等的、带权可松弛约束**而非带外打分函数，使硬/软约束共享同一形式表示与同一套检查与解释机制，避免了两套语义的割裂。
- **解释驱动的交互闭环

**：**偏好校验失败时返回的是**导致冲突的最小硬约束集合**（DL 的不一致最小公理集 / MiniZinc 的 MUS），且以**共享词汇表中的具名约束**而非自由文本形式回传。这一设计把"诊断责任"牢牢留在符号侧，LLM 只负责把结构化结果转述给用户并主持协商——切分了神经与符号的职责边界，也降低了 LLM 自由生成冲突解释时的幻觉风险。
- **分工层次清晰**：明确区分"静态可满足性"（个体偏好 vs 硬约束，本体层解决）与"联合可行性"（多偏好在同一资源上的竞争，调度层解决），避免了把所有冲突一股脑塞进单一求解器。
- **可推广性论证具体而非空泛**：多租户楼宇气候控制这一同构例子（租户软偏好 vs 设施经理高权威上限 vs 设备数据表硬限制，共享同一受限供给）足以说明架构不绑定能源领域。
- **对 LLM 能力边界的清醒认识**：作者不让 LLM 承担一致性判定或冲突检测，只让它做引出与沟通，这符合当前 LLM 在严格逻辑推理上的可靠性现状。

## 8. 不足与局限

- **核心内容未实现**：作者自述偏好扩展与 LLM 助手"尚未构建"（not yet built），反馈循环"仅在 OWL 路径上被演练过"。全文是设计蓝图，不是可运行系统。
- **关键语义悬而未决**：偏好究竟寄宿于 **ConfigVoc** 还是 **ConfigDL** 是全文最重要的未决问题。若选 ConfigDL，可松弛约束在 OWL "全有全无"的公理语义下**没有天然归宿**；若选 ConfigVoc，则放弃 DL 推理机的原生执行优势。作者只列出两条路径的权衡，未给出决策依据或原型验证。
- **静态检查存在能力盲区**：数值冲突的检测依赖 **DL-safe SWRL + 算术内建**，而其对**开放（未接地）变量**的公式约束可行性**超出能力范围**。这意味着"个体偏好 vs 硬约束"的静态可满足性检查在最需要它的场景（约束含未定变量、需调度才接地）恰恰可能失效——论文对此盲区着墨不足。
- **优先级与多目标语义未形式化**：跨利益相关者的权威排序、优先级数值如何跨聚合比较、多个软约束违反代价如何合成，均只被列为研究议程，没有给出偏序/全序假设或聚合函数。
- **接地忠实性（faithful grounding）缺乏保障机制**：一致性检查只能发现"约束集自相矛盾"，**无法发现"约束被错误接地"**（即助手把用户话语翻译成了语义不同但内部一致的约束）。论文承认这是议程项，但未提出检测手段，而这恰是 LLM 中介流程最现实的失效模式。
- **循环收敛性未论证**：重新协商可能不终止（用户持续提出新偏好、或反复在冲突约束间摇摆），论文未给出轮数上界、终止条件或回退策略。
- **冲突下推的复杂度未讨论**：软偏好之间"故意不互测"虽在语义上合理，却把组合冲突全部留给调度器，可能引发调度层的组合爆炸；论文未做复杂度分析。
- **"交互时间"只是口号**：全文多次强调推理需保持在交互时间内，却未给出延迟预算、规模假设或任何性能估算。
- **证据基础薄弱且来源单一**：仅 FLEXI 一个用例、两个手工情景，均来自作者参与资助的项目，属示意性正面举例，存在确认性偏差；无对照、无用户研究、无失败案例分析。
- **篇幅与深度受限**：8 页 position paper 的体量使上述每个开放问题都只能点到为止。

## 9. 启示与可借鉴之处

- **问题定义本身可复用**："符号规范从何而来"是一个可独立成立的研究问题，本文的框定方式（异构来源 + 权威不等 + 硬软混存 + 需调和）可作为后续工作的标准问题陈述。
- **一条可迁移的设计模式**：**LLM 负责引出与沟通、本体/求解器负责判定与诊断、解释以结构化具名对象回传**——这一"神经-符号职责切分 + tool-call 式解释回环"可移植到任何 LLM 驱动的需求工程、配置或规划系统。
- **表示层面的建议值得采纳**：把偏好建成一等可松弛约束而非带外打分函数，使硬软约束共享检查与解释机制，是避免双语义割裂的实用准则。
- **可直接立项的后续工作**：偏好扩展原型（选定 ConfigVoc/ConfigDL 宿主）、跨群体优先级语义、接地忠实性检测、以及针对"获取循环本身"（静态检查捕获率、协商轮数、交互时延）的首个评测——作者已把评测口径列出，便于他人接续。
- **对工业实践的价值**：为 Siemens 类产品配置平台（CONTO）向"多利益相关者偏好感知"演进提供了低破坏性的增量路线（在既有本体上叠加 `pref:` 词汇），而非推倒重建。
